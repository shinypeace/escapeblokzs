# VK Mini Apps

Приложение: [Кубоход — VK App 54824611](https://vk.com/app54824611).

Адрес игры для полей веб-версии, мобильной версии и iFrame в настройках этого приложения:

```text
https://shinypeace.github.io/escapeblokzs/
```

В репозитории используется официальный **@vkontakte/vk-bridge 3.0.2**, локальная ESM-сборка в `dist/vendor/vk-bridge-3.0.2.js`. CDN не нужен. Лицензия MIT сохранена рядом. Идентификатор приложения публичный; секретные ключи и токены в проект не добавляются.

## Что подключено

- `VKWebAppInit` и получение текущего пользователя через `VKWebAppGetUserInfo`.
- Постоянный нижний баннер через `VKWebAppShowBannerAd`, если реклама поддерживается и у VK есть доступное объявление. Баннер запрашивается при запуске и возвращении в приложение. После межэкранной рекламы он запрашивается повторно.
- Межэкранная реклама: не раньше третьей завершённой попытки и не чаще одного вызова за 90 секунд. Единственная точка вызова — завершение уровня или падение. Таймеров, открывающих рекламу в процессе игры, нет.
- Пауза звука/игры при сворачивании клиента и на время рекламы; восстановление после её закрытия.
- Облачный прогресс через `VKWebAppStorageGet` / `VKWebAppStorageSet`, с отдельными ключами для ID текущего пользователя.
- Отключение нативного жеста «назад», если клиент поддерживает `VKWebAppDisableSwipeBack`, чтобы он не перехватывал игровые свайпы.

Обычный переход по ссылке GitHub Pages оставляет игру в браузерном режиме с локальным сохранением. VK-функции включаются только при запуске приложения **54824611** внутри VK WebView/iFrame и после успешного ответа SDK. Одни лишь параметры `vk_user_id` или `vk_app_id` в адресе не создают вход в аккаунт. Параметр пользователя из URL не используется как источник ID.

## Реклама и публикация

1. В настройках VK-приложения **54824611** укажите HTTPS-адрес GitHub Pages выше для нужных платформ.
2. Откройте игру через [vk.com/app54824611](https://vk.com/app54824611), затем проверьте запуск в мобильном VK и в десктопной версии.
3. В кабинете владельца приложения подключите доступную монетизацию и выполните требования VK к приложению и рекламным размещениям. Наличие SDK в исходниках само по себе не включает монетизацию: её доступность, модерация и фактическая выдача объявлений управляются VK.
4. Для проверки рекламы используйте инструменты тестирования, доступные в кабинете VK. При отсутствии выдачи игра продолжает работать; фиктивный баннер и начисление выдуманных рекламных наград не показываются.

Баннер запрашивается как нижний горизонтальный `resize`, `height_type: compact`, `can_close: false`. Ещё **до загрузки SDK** при распознанном запуске внутри VK игра резервирует снизу 96 CSS-пикселей. Это запас для компактного баннера на время медленного ответа нативного клиента. Положительный `banner_height` из ответа или `VKWebAppBannerAdUpdated` заменяет запас реальным размером; нижняя безопасная область берётся из `VKWebAppGetConfig`, `VKWebAppUpdateConfig` и `VKWebAppUpdateInsets`.

Игра учитывает фактическое уменьшение высоты WebView при `resize`, поэтому не вычитает уже занятую нативным клиентом область второй раз. До изменения размеров защита сохраняется; если клиент вместо `resize` использует `overlay`, кнопки также остаются выше баннера. Неполные ответы `{result: true}`, нулевые размеры, временные ошибки и медленный Promise не обнуляют отступ. Одновременно выполняется только один запрос показа, даже при нескольких событиях восстановления. При неполном ответе/ошибке выполняется одна дополнительная проверка `VKWebAppCheckBannerAd`, без фонового опроса. Устаревший ответ не заменяет более новое событие геометрии или закрытия.

Запас снимается при подтверждённом отсутствии объявления на первом показе, неподдерживаемом методе либо явном закрытии/успешном скрытии. Ошибка обновления не означает, что прежний нативный баннер исчез. В обычном браузере место под рекламу не резервируется. Фактический показ объявления на каждой платформе зависит от SDK и рекламного инвентаря.

Проверить настоящую выдачу рекламы и аккаунтное хранение можно только внутри указанного VK-приложения с доступом его владельца. Автоматические тесты используют имитацию официального интерфейса Bridge и проверяют порядок вызовов и обработку ошибок.

## Контракт адаптера

`dist/vk-platform.js` экспортирует `platform` и публичную константу `VK_APP_ID = 54824611`.

```js
import { platform } from './vk-platform.js';

const { isVK, userId } = await platform.init();
const remoteJSON = await platform.loadSave();
// Проверить формат, выбрать/объединить прогресс в storage.js.
// Только после этого разрешать публикацию итогового сохранения:
platform.queueSave(JSON.stringify(validatedSave));
```

| Метод/поле | Назначение |
| --- | --- |
| `init()` | Идемпотентная инициализация; возвращает `{ isVK, userId, bannerHeight }`. Отступ резервируется синхронно при запуске внутри VK. Баннер запрашивается в фоне, не задерживая меню; ответы уточняют отступ через `onBannerChange`. |
| `loadSave()` | JSON-строка либо `null`. Вызывается до первой записи; схема игры проверяется в `storage.js`. |
| `queueSave(json)` | Сохраняет последний снимок с задержкой 1200 мс; возвращает, принят ли он в очередь. |
| `flushSave()` | Сериализует незавершённые записи и немедленно отправляет очередь. |
| `afterRound('win' / 'loss')` | Проверяет частоту и доступность, затем показывает межэкранную рекламу; Promise завершается после закрытия/отмены. |
| `onPause(fn)`, `onResume(fn)` | Обработчики жизненного цикла и рекламной паузы; возвращают функцию отписки. |
| `onBannerChange(fn)` | Нижний отступ в CSS-пикселях; первый вызов сразу при подписке. |
| `onAccountChange(fn)` | Обнаружена смена VK-аккаунта; передаёт новый ID. Требуется новая сессия игры/перезагрузка. |
| `isVK`, `userId`, `cloudReady`, `isAdOpen`, `bannerHeight` | Текущее состояние адаптера. |

**Граница раунда:** игра должна ожидать `await platform.afterRound(outcome)` с заблокированным переходом к следующему раунду. Проверка наличия рекламы асинхронная; блокировка исключает появление опоздавшего объявления после начала следующего уровня. Во время самого показа адаптер удерживает рекламную паузу до завершения Promise SDK.

**Надёжность сохранений:** запись запрещена до успешного первоначального чтения. Ошибка чтения не считается пустым облаком, поэтому локальный прогресс не перетирает недоступное сохранение. Данные кодируются UTF-8/base64 и делятся на ASCII-части до 2800 байт. Максимальный снимок — 512 КиБ. Используются два банка; указатель переключается лишь после записи всех частей. Длина и контрольная сумма проверяются при чтении. При ошибке записи предыдущий банк остаётся опубликованным, а последняя версия остаётся в очереди. Одновременные сохранения выполняются последовательно.

При возвращении в VK и перед записью ID пользователя проверяется повторно. Смена аккаунта останавливает облачную очередь; старый прогресс не записывается под новым ID. Локальное хранилище приложения также должно быть разделено по ID. VK Storage является хранилищем платформы, а не серверной системой противодействия читам. Для серверных платежей/рейтингов понадобятся отдельный сервер и проверка подписанных параметров запуска; клиентская проверка URL их не заменяет.

## Проверки

```sh
node --check dist/vk-platform.js
node --test tests/vk-platform.test.mjs
```

Тесты покрывают обычный браузер, чужой App ID, SDK-пользователя, синхронный запас до загрузки SDK, задержку показа дольше обычного тайм-аута, неполные размеры, `resize`/`overlay`, безопасную область, восстановление без повторных запросов, устаревшие ответы, отсутствие/закрытие объявления, гонку первоначального чтения с записью, большие Unicode-сохранения, повреждённое/недоступное облако, незавершённую запись, последовательность сохранений, отмену рекламы, рекламную частоту и смену аккаунта.
